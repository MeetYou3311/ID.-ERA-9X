# 方案 B · 跨用户去重新建说明

本目录是「方案 B」的独立实现，**不改动现有页面**：
- 前端 `index.html` 复用现有的根目录 `data.json`（文案仍由 `admin.html` 后台管理）。
- 跨用户的「已领数量」由 **Cloudflare Workers + KV** 存储，公开页面不含任何写权限。

## 目录结构
```
v2/
  index.html      # 跨用户版前端（部署到 GitHub Pages 的 /v2/）
  worker.js       # Cloudflare Worker（KV 计数服务）
  wrangler.toml   # Worker 配置
```

## 一、部署无服务器计数服务（Cloudflare，免费档够用）

> 前置：注册 Cloudflare 账号（免费）。国内访问建议给 Worker 绑一个自定义域名并走 Cloudflare 代理，比默认 `*.workers.dev` 稳。

1. 安装并登录 Wrangler（Node.js 环境）：
   ```bash
   npm install -g wrangler
   wrangler login
   ```
2. 创建 KV 命名空间：
   ```bash
   wrangler kv namespace create CLAIM_KV
   ```
   终端会返回一段 JSON，里面有 `"id": "xxxxxxxx"`。把该 id 复制到 `wrangler.toml` 的 `id = "REPLACE_WITH_YOUR_KV_ID"` 处。
3. 部署 Worker：
   ```bash
   cd v2
   wrangler deploy
   ```
   部署成功会得到一个地址，形如 `https://era9x-claims.<你的子域>.workers.dev`。
4. 把这个地址填进 `v2/index.html` 顶部的：
   ```js
   var WORKER_URL = "https://era9x-claims.xxxx.workers.dev";
   ```

## 二、部署前端（GitHub Pages，复用现有仓库）

`v2/` 目录直接推到仓库即可，会自动出现在：
`https://meetyou3311.github.io/ID.-ERA-9X/v2/`

- 已填 `WORKER_URL` → 启用跨用户计数（甲领了，乙立刻看到少一条）。
- 留空 → 自动降级为「仅本机去重」，页面照常可用。

## 三、数据模型说明

`data.json` 每条文案可带可选字段 `stock`（总库存）：
```json
{ "id": "seed-1", "title": "升级前须知", "content": "...", "stock": 100 }
```
- 有 `stock`：剩余 = stock − 全网已领；剩余为 0 显示「已领完」并禁用复制；剩余 ≤ 低库存阈值时顶部预警。
- 无 `stock`：使用 `COPY_SETTINGS.defaultStock`（前端默认 100），或设为 `stock: 0` 表示不限量（永不耗尽，只统计已领次数）。

## 四、安全与注意

- Worker 只持有 KV 的读写，**没有 GitHub 仓库的任何权限**，公开 JS 里也不含 Token。
- KV 是最终一致性的边缘存储，极高并发下计数可能有极小误差（分享场景可忽略）。
- 若担心有人刷接口把库存耗光，可给 `/claim` 加简单校验（如限定来源域名、或加一个轻量密钥），按需在 `worker.js` 中补充。
