# 方案 B（仓库版）· 跨用户去重部署说明

本方案**不使用 KV**，而是把跨用户的「已领数量」直接写回你 GitHub 仓库里的 `claims.json`：
- 公开前端只调用 Worker 的两个接口 `/counts`（读）、`/claim`（写），**不含任何 Token**。
- GitHub Token 以 **Worker 秘密 `GH_TOKEN`** 注入，只在 Cloudflare 边缘运行，不进公开代码。

> 注意：方案 B 仍然要部署一个**函数（Cloudflare Worker）**。纯静态前端无法做跨用户写数据（否则 Token 会暴露）。Cloudflare 是「发布一段函数」，不用你买/管服务器。

## 一、部署 Worker（Cloudflare，免费）

1. 安装并登录 Wrangler（需 Node.js）：
   ```bash
   npm install -g wrangler
   wrangler login
   ```
2. 设置 GitHub Token 为秘密（粘贴你已有的、对该仓库有 **Contents: write** 的 PAT；就是后台 admin.html 用的那个）：
   ```bash
   cd v2
   wrangler secret put GH_TOKEN
   ```
   > 密钥只存在 Cloudflare，不会写进 `wrangler.toml` 或前端。
3. 部署：
   ```bash
   wrangler deploy
   ```
   成功后得到地址，形如 `https://era9x-claims.<你的子域>.workers.dev`。

4. 把该地址发给帮你部署的人（或直接填进 `v2/index.html` 顶部的 `WORKER_URL`），跨用户计数立即生效。

## 二、前端（已就绪，部署在 GitHub Pages）

`v2/index.html` 复用根目录 `data.json`（文案仍由 `admin.html` 后台管理），并通过 `WORKER_URL` 调用上面的 Worker：
- 已填 `WORKER_URL` → 启用跨用户计数（甲领了，乙立刻看到少一条，读取走 GitHub API 实时返回，无 Pages 重建延迟）。
- 留空 → 自动降级为「仅本机去重」。

线上地址：`https://meetyou3311.github.io/ID.-ERA-9X/v2/`

## 三、数据模型

- `data.json`：文案列表（含可选 `stock` 总库存；无则前端用默认 100）。
- `claims.json`：跨用户领取计数，格式 `{ "seed-1": 3, "seed-2": 1 }`，由 Worker 自动维护，无需手动编辑。

## 四、注意

- **每次领取会在仓库产生一次提交**（写 `claims.json`）。内部分享、访问量不大时完全没问题；若介意提交数，可改用方案 A（KV 版，零提交）。
- 极高并发下计数可能有极小误差（GitHub 内容接口非事务性），分享场景可忽略。
- `ALLOW_ORIGIN` 在 `worker.js` 默认 `*`，生产建议改成你的 Pages 源站以收紧跨域。
